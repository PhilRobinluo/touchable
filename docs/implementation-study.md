# 实现研究笔记

## 一句话判断

这个项目可行，但适合做“关键点触觉提示”，不适合做“连续纹理震动”。

## 公开 API

Apple 提供 `NSHapticFeedbackManager`，用于支持 Force Touch 触控板的 Mac 上触发触觉反馈。

可用模式主要有：

- `generic`：通用短促反馈。
- `alignment`：对齐、吸附、到达边界时的反馈。
- `levelChange`：离散等级变化时的反馈。

这三个模式足够做第一版“边缘感”和“刻度感”。

## 位置监听方案

### 方案 A：轮询光标位置

使用 `NSEvent.mouseLocation` 定时读取光标位置。

优点：

- 简单。
- 不需要先做完整 App。
- 适合快速验证手感。

缺点：

- 不是直接读取手指在触控板上的绝对位置。
- 更像“光标边界反馈”，不是“触控板表面区域反馈”。

### 方案 B：全局事件监听

使用 `NSEvent.addGlobalMonitorForEvents` 监听鼠标移动、滚动、拖拽等事件。

优点：

- 更接近真实交互。
- 可以对滚动、拖动、窗口移动做更细的反馈。

缺点：

- 可能需要辅助功能权限。
- 只能监控事件副本，不能修改系统事件。
- 需要做好性能和隐私边界。

### 方案 C：只在自定义 App 内增强

在自己的 App 或 WebView 容器中，用 AppKit/SwiftUI 控制交互区域，并触发 haptic。

优点：

- 最稳、最符合平台规则。
- 手感可以做得最精确。

缺点：

- 不是系统全局体验。

## 第一阶段实验

目标是找到“舒服的边缘感”：

- 屏幕边缘 20px、28px、40px 对比。
- 区域分割 2x2、3x2、3x3 对比。
- 节流 0.12s、0.18s、0.25s 对比。
- 边缘使用 `alignment`，区域切换使用 `levelChange`。

## 风险评估

按当前实现方式，风险很低。

原因：

- 触觉反馈由系统公开 API 触发。
- 系统会根据当前设备、辅助功能设置和用户偏好执行。
- 不是直接控制马达电压、频率或波形。
- 有节流，不做高频持续震动。

需要避免：

- 每秒几十次连续触发。
- 后台长时间无节制运行。
- 使用私有 API 或驱动层 Hack。
- 未说明用途就申请过宽权限。

## 产品方向

最小产品可以是菜单栏 App：

- 开关：启用 / 暂停。
- 模式：边缘、网格、滚动、拖拽。
- 强度感：通过频率和模式组合模拟，不直接控制真实强度。
- 设备检查：提示是否支持 Force Touch / Magic Trackpad 2。
- 权限解释：如果需要辅助功能权限，只解释它用于监听光标移动，不读取内容。
